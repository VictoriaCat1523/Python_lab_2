# Лабораторная работа № 2 — Streamstats

Программа обрабатывает события из CSV или JSONL по одному за раз,
считает общую статистику и сохраняет JSON-отчёт.

## Установка

Нужен Python 3.10 или новее. Из каталога `Python_lab_2`:

```bash
python -m pip install -e .
python -m pip install pytest ruff
```

## Примеры запуска

```bash
python -m streamstats --help
python -m streamstats analyze data/sample.csv --format csv --output report.json
python -m streamstats analyze data/sample.jsonl --format jsonl
python -m streamstats analyze data/sample.jsonl --format jsonl --skip-invalid
```

Несколько файлов одного формата:

```bash
python -m streamstats analyze data/sample.csv data/sample2.csv --format csv --output report.json
```

Если `--output` не указан, JSON выводится на экран. Предупреждения и ошибки
пишутся в stderr и не смешиваются с JSON.

## Формат события

Обязательные поля: `timestamp` (строка ISO 8601), `level`
(`DEBUG`, `INFO`, `WARNING`, `ERROR`, `CRITICAL`), `source` (непустая строка),
`message` (строка, может быть пустой).

- Временная метка со смещением переводится в UTC для сравнения и вывода.
- Дата без смещения трактуется как UTC.
- Поле `source` очищается от пробелов в начале и конце.
- В JSONL каждая строка — отдельный JSON-объект. Пустая строка считается
  ошибочной записью.
- Поля, не относящиеся к модели, игнорируются, кроме лишних CSV-столбцов.
- Для CSV используется заголовок; имена столбцов должны совпадать с именами
  обязательных полей. Если в строке не хватает столбцов, она считается неверной.
- Номер CSV-строки обозначает **физическую строку завершения записи**;
  поле с переносом строки может занимать несколько строк.

## Ошибочные записи

Без `--skip-invalid` программа сообщает номер файла, его путь и строку неверной записи и
завершается с кодом 2. С этим флагом плохие строки пропускаются, выдаётся
`WARNING` и увеличивается `skipped_rows`.

Важный случай: `csv.DictReader` не всегда может продолжить чтение после
повреждённых кавычек, поскольку границы записей становятся неопределёнными.
В таком случае парсер сообщает ошибку и прекращает чтение текущего файла.
Ошибочные **значения** полей CSV не мешают чтению следующих записей.

## Поля отчёта

| Поле | Значение |
| --- | --- |
| `total_events` | количество корректных событий |
| `by_level` | количество событий каждого уровня |
| `by_source` | количество событий каждого источника |
| `top_error_sources` | максимум 5 источников по `ERROR` + `CRITICAL` |
| `first_timestamp` | минимальная метка в UTC или `null` |
| `last_timestamp` | максимальная метка в UTC или `null` |
| `skipped_rows` | число пропущенных записей |

При равенстве количества ошибок источники сортируются по имени.

## Проверка

```bash
python -m pytest
python -m ruff check .
python -m streamstats --help
```

Код разбит на `models.py` (валидация), `parsers.py` (файлы), `analysis.py`
(статистика), `report.py` (JSON), `errors.py` (ошибки), `__main__.py` (CLI).
